# 伙伴端工作台设计约束

本规范维护伙伴端页面的视觉、交互和审核意见契约。原型决定产品内容与模块结构；通用视觉遵循本规范，用户明确指定的例外优先。现有实现不自动覆盖规范。

阅读导航：基础视觉与布局见第 1–5 节；列表、状态和操作见第 6–7 节；特殊工作台模块见第 8–9 节；原型与人工验收见第 10–11 节；报告详情及警示弹窗见第 12 节；审核意见见第 13 节；填写页富文本间距、提示、日期及成果入口见第 14 节；预算密集表格见第 15 节。第 13 节编号保持稳定，供 `AGENTS.md` 引用。

实现参考：`src/layouts/PartnerLayout.vue`、`src/views/Dashboard.vue`、`src/styles/common.css` 提供工作台骨架；`src/views/ProjectForm.vue`、`src/views/ReportForm.vue` 提供填写页；`src/views/ReportDetail.vue` 提供报告详情。修改前核对实际代码及当前需求，不直接照搬历史差异。

## 1. 设计基调

- 定位：桌面端项目管理后台，信息密度中等，强调清晰、可信和轻量现代感。
- 页面骨架：深海军蓝固定侧栏、半透明白色固定顶栏、冷灰蓝页面底色、白色内容卡片。
- 品牌色以蓝色表达主要操作和当前导航，以绿色表达生态、品牌和正向进度。
- 装饰克制：常规卡片使用细描边、16px 圆角和浅阴影；渐变只用于品牌标识、激活导航、特定封面及独立功能入口。
- 不使用大面积高饱和色填充正文区域，也不为普通业务模块引入紫色 AI 视觉语言。

## 2. 基础令牌

### 字体

- 字体栈与线上脚手架一致：`-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', 'Helvetica Neue', Helvetica, Arial, sans-serif, 'Apple Color Emoji', 'Segoe UI Emoji', 'Segoe UI Symbol'`。通过 `src/styles/common.css` 的 `--font-family` 统一维护；控件、弹层与 SVG 使用同一字体栈，不额外加载网页字体。
- 全项目字号以 px 为单位，公共规则集中在 `src/styles/common.css`，页面和组件仅保留下表列出的例外。禁止逐页重复默认字号，禁止通过增加高优先级选择器或 `!important` 反复覆盖字号。

| 语义 | 公共规则 | 实现与边界 |
| --- | --- | --- |
| 正文、字段标签/内容、说明、表格正文 | `14px` | `--text-14`；由根容器继承，正文常规字重，业务字段既有 500 等强调字重保留 |
| 按钮、输入框、文本域、选择器、单选/复选文字、输入提示、富文本输入正文 | `14px` | 公共覆盖原生及 Ant Design Vue 控件，含挂载到 body 的弹层；普通控件不再保留页面级 16px/18px 声明 |
| 页面/模块/富文本标题、项目与机构主名称 | `16px / 700` | `--text-16`；h1–h6 和公共业务标题选择器统一维护，字段标签不因内容较长就变成标题 |
| 状态胶囊、正负状态标签 | `13px` | `--text-13`；既定尺寸、颜色和交互不变，项目编号/机构名称等信息色块仍用正文规则 |

正文基础行高 `1.5`；页面已有专项行高和字重可保留。审核标题按钮使用 `font: inherit` 继承标题语义，普通按钮为 14px。字体变化不要求重写既有颜色、布局、间距、表格列宽、审核数据契约或业务交互。

### 间距、圆角和阴影

- 页面左右内边距：28px；内容顶部 20px；页面底部保留 64px。
- 主栏与侧栏间距：24px；主栏卡片间距：20px；侧栏卡片间距：18px。

- 卡片标题栏左右内边距 20px；主栏标题栏最小高度 64px，侧栏标题栏最小高度 56px。

## 3. 页面骨架与响应式

- 默认桌面布局预留 256px 固定侧栏和 72px 固定顶栏。
- 工作台内容采用双栏：左侧主内容 `minmax(740px, 1fr)`，右侧信息栏固定 400px，间距 24px；内容网格最小宽度 1164px。
- 右侧信息栏在宽、高足够时从顶栏下方粘滞显示，顶部偏移 92px。
- 视口不超过 1600px 时，侧栏缩至 220px，推荐卡由三列改为两列，页面维持至少 1280px 的桌面工作区。
- 视口不超过 1366px 时，侧栏折叠为 72px，仅保留图标；品牌文字、导航文字、箭头和子菜单隐藏。新增导航必须提供可理解的图标与 `title`。
- 不把当前伙伴端改造成移动端卡片流，除非原型或需求明确要求移动适配。

## 4. 导航与顶栏

- 页面级返回按钮统一固定悬浮在内容区右上方，文案统一为“返回”，搭配 `arrow-left` 图标。按钮使用 `position: fixed`，桌面端定位为 `top: 92px; right: 28px`，位于 72px 固定顶栏下方并与内容区 20px 顶部间距对齐；层级低于顶栏、高于正文，页面滚动时持续可见。
- 复用 `detail-back-row` 与 `detail-back` 公共样式；原按钮容器至少保留 `38px` 高度作为布局占位，防止按钮脱离文档流后首个内容模块上移。报告详情等使用独立标题行的页面也应保留等高占位。
- 返回目标、未保存提醒及禁用逻辑沿用各页面既定行为。在 1920px、1440px、1366px 以及出现横向滚动的窄桌面视口下，人工确认按钮不与顶栏、垂直滚动条、底部固定操作栏或弹窗重叠。

- 一级导航高度 48px、圆角 11px，图标与文字间距 12px；默认文字 `#b9c8d7`。
- 悬停使用低透明白色背景；激活项使用 `#1677ff → #4597ff` 横向渐变、白字和轻蓝阴影。
- 子导航高度 40px，左侧缩进约 46px；激活态用半透明主蓝背景。
- 退出入口固定在导航底部语义位置，使用危险红 `#ff6b76`，与普通导航分隔。
- 顶栏高 72px、左右内边距 28px；左侧面包屑，右侧通知、分隔线及用户信息。图标型按钮保持约 40×40px 的稳定点击区域。

## 5. 卡片与模块标题

- 卡片保持白底、细边框和浅阴影，不在同一页面混用明显不同的圆角体系。
- 主模块标题使用 16px、700 字重，标题前可放 4×20px 圆角竖条区分业务模块。
- 已有竖条语义：进行中项目为绿色；募捐申请为紫色渐变；招募推荐为橙色；最新招募为蓝色。相同模块沿用相同颜色。
- 侧栏标题使用 Ant Design 图标，不再添加竖条；系统通知为金色、机构信息为青绿、常见问题为蓝色、制度文件为靛蓝色。
- 标题栏右侧的“查看全部”、搜索和筛选保持右对齐，不挤压标题。
- 项目填写页模块标题下方的审核意见交互提示必须由该模块的审核意见数据控制：仅当模块内至少存在一条有效审核意见时显示；没有审核意见时不显示提示文案，也不保留空白占位或使用普通说明文案替代。

## 6. 列表、信息层级与长内容

- 列表以细分隔线分组，最后一项不显示底部分隔线。
- 标准业务条目按“80px 缩略图 / 自适应正文 / 可选操作区”组织；正文容器必须设置 `min-width: 0`。
- 列表第一列为头像，或第一列内容包含头像 / Logo 时，头像左边缘统一距列表内容区左侧 `20px`，与伙伴工作台“进行中的项目”列表对齐。表头与单元格的首列左内边距均设为 `20px`；不得因头像作为表格列而沿用组件默认内边距。
- 各个列表中的项目名称必须完整显示，超长时自动换行。适用于伙伴工作台、SEE 工作台、已申请项目、进展/结项及后续新增列表，包括可点击的项目名称。使用 `min-width: 0; white-space: normal; overflow-wrap: anywhere` 和约 `1.5–1.6` 行高；禁止省略号截断、行数限制或固定高度裁剪，不得仅靠悬停提示展示完整名称。行高随内容自然撑开，状态、日期和操作区保留各自空间，不得被长名称挤压或遮挡。
- 桌面列表形式页面统一采用 `width: 100%`、`min-width: 1140px`，铺满容器并由容器实际可用宽度决定是否横向滚动。适用于项目、招募、机构、筹款规划、框架协议、募捐申请、请款、收益汇总、地区数据及收益详情等独立业务列表；数据下载页仅统一操作列宽度为 `120px`，其余布局保留既定规则。工作台卡片列表、表单录入明细、预算及展开行内嵌明细沿用各自专项规则，不强制套用独立列表的最小宽度。
- 横向滚动仅在容器可用宽度不足以容纳表格时触发，滚动容器使用 `overflow-x: auto` 或 Ant Design Vue 的 `:scroll="{ x: true }"`。不得按 `1440px` 或其他视口断点强制加宽表格、强制产生滚动条；侧栏在 `1600px` 缩窄、`1366px` 折叠后，应随新的可用宽度自然重新计算。`1440px` 及以上作为完整展示的人工验收基准，不是强制滚动断点。项目名称列不设固定宽度，优先承接固定业务列之外的剩余空间，长名称完整换行；其他列宽按本节规定和明确业务需求设置。
- 上述桌面业务数据列表的固定列宽统一为：业务 ID 列 `110px`、项目类型 `110px`、所有状态列固定为 `150px`（包括通用状态、项目状态、进展/结项状态、申请状态及筹款状态）、日期或时间 `120px`；用户明确指定的业务列宽优先。凡有操作列，统一宽 `120px`、水平居中并固定在表格右侧，采用 Ant Design Vue 的 `fixed: 'right'`，或已有的右侧粘滞单元格实现。没有操作列的列表不新增操作列；选择列宽度按其组件约定单独设置。数据下载页的操作列同样统一为 `120px`，其余列宽、固定方式及布局行为保留既定规则。
- 列表公共样式集中维护于 `src/styles/common.css`，通过显式类按需复用：`shared-list-table` 负责滚动主体表格铺满及 1140px 最小宽度，`shared-list-fixed` 仅供原本使用固定表格布局的页面；`shared-list-inset-8` / `shared-list-inset-12` 保留现有单元格左右留白，`shared-list-first-inset` 为首列 20px 留白，`shared-list-wrap` 为整表文字换行。`shared-list-operation-spacing` 统一已采用的操作按钮图标间距，`shared-list-tabs` 复用标签页外观；收益详情可使用 `shared-list-detail`、`shared-list-title`、`shared-list-detail-filters`。新增页面优先复用，已有页面不得仅为使用公共类而改变已确认的列宽、对齐、换行、留白或布局方式。招募汇总主表/展开明细、收益汇总原生表格、数据下载和固定列副本仍保留对应专项规则。此次抽取已做源码核对；重新构建和 HTTP 验证不能替代抽取后的人工验收。
- 固定操作列遮盖阴影：适用于桌面业务列表的右侧固定操作列；左侧阴影统一复用筹款规划所用的 Ant Design Vue 1.7.8 参数 `box-shadow: -6px 0 6px -4px rgba(0,0,0,.15)`，使用模糊阴影，不用线性渐变或实线替代。仅在右侧仍有未滚入视区的表格内容、固定列正在遮盖其他列时显示；无横向溢出或滚动到最右侧时隐藏。阴影须沿表头、各数据行及行分隔线连续，不出现逐行收缩、断层或明显接缝；操作列背景应不透明并保留表头、普通行和悬停行的既定底色，阴影层设置 `pointer-events: none`，不影响点击、菜单或行展开。
- 固定列实现优先复用组件默认阴影及滚动状态。已有粘滞单元格实现可沿用招募汇总的伪元素：`position: absolute; top: -8px; bottom: -8px; left: 0; width: 30px; box-shadow: -6px 0 6px -4px rgba(0,0,0,.15); clip-path: inset(8px 100% 7px -10px); pointer-events: none`，通过裁切只保留左侧模糊阴影并覆盖行分隔线；以 `opacity` 和 `.3s ease` 切换显示。招募汇总当前按 `scrollWidth - clientWidth - scrollLeft > 1` 判断显示，并在滚动、窗口尺寸和页面内容更新时重新计算；其他页面使用各自实际滚动容器，不依赖固定视口断点。此段参数是粘滞实现参考，不要求将组件默认固定列改造成粘滞列，也不授权批量修改历史页面。
- 录入型业务明细表格统一将“序号”列固定为 `70px`、“操作”列固定为 `130px`，两列均按可完整容纳表头和常用操作的最小值设置，不随表格宽度按比例扩张。省市区、人员、风险、监测等同类录入表格使用相同参数；其余内容列分配剩余宽度，内容较长时自然换行。该规则不覆盖项目列表中下拉操作列的 `120px` 专用规范。
- 编辑/填写页的录入型表格，“序号”列和“操作”列的表头、单元格内容统一水平居中；操作列中的编辑、删除等行内按钮保持同一行，不因文字换行而上下堆叠。适用于项目、报告及后续同类编辑页中的区域、人员、产出、风险等明细表格；其余业务列沿用各自展示规则，用户明确要求的例外优先。当前创绿家编辑页组织信息表已完成代码核对，居中效果、长内容和按钮同排仍需人工验收；本规范更新不代表其他历史页面已全部整改，也不授权批量修改。
- 描述使用次级文字色与 1.55 左右行高；项目多段描述可使用 `white-space: pre-line`。
- 时间、联系方式、项目组等元信息优先使用图标加文本；允许换行，但同类元信息的颜色与间距必须一致。
- 逾期行使用由 `#fff3bf` 过渡到近白色的浅黄色背景，并显示金色警示文字；不要仅依赖背景色传达逾期。

### 项目列表业务标识

项目列表中的项目编号、机构名称和招募名称是三种固定业务语义，必须使用各自的图标与颜色，不得互换或统一成普通次级文字。

- 布局：项目标题单独占第一行；标题与下一行标识之间保留约 `10px` 的视觉间距。项目编号与机构名称位于第二行，使用 `flex` 横排并保持 `8px` 间距；招募名称位于第三行。
- 通用外观：标识采用“图标 + 文本”，内边距 `2px 7px`、圆角 `3px`，文字保持正文常规字重。正文容器必须设置 `min-width: 0`，不得挤压状态、日期或操作列。
- 项目编号：使用 `flag` 图标，文字色 `#62BFE6`，背景色 `#EFFAFF`。该样式仅表示项目编号，例如 `ZZ-1764740216`。
- 报告编码：在报告详情的“项目基本信息”模块标题格内，紧跟项目编码展示；使用 `file-text` 图标，文字色 `#5B8FF9`，背景色 `#F0F5FF`，内边距 `2px 7px`、圆角 `3px`。该样式仅表示进展/结项报告编码，例如 `P-001006`。
- 机构名称：使用 `bank` 图标，文字色 `#61BD98`，背景色 `#F1FBF5`。该样式仅表示项目所属或申报机构。
- 招募名称：使用 `notification` 图标，文字色 `#B081D0`，背景色 `#FAF4FF`；悬停时文字色 `#9360B8`、背景色 `#F5EAFF`。招募名称是可打开招募详情的入口，长文本应在项目名称列内自然换行并完整展示，不使用省略号截断。
- 三类标识的颜色必须同时配合图标和文本表达含义，不能只依靠底色区分。

## 7. 状态与操作

### 状态标签

状态类胶囊配色以用户确认的工作台与项目列表样式为强制规范，适用于项目状态、募捐申请状态等业务状态。新页面只要展示状态，就必须复用本节样式，不得使用 Ant Design 预设标签色、旧页面近似色或自行扩展的渐变色替代。

- 标签统一为 `112px × 24px`，`box-sizing: border-box`，1px 实线边框，`5px` 圆角；文字水平和垂直居中、单行不换行。“募捐申请通过”胶囊的圆角为统一基准。
- 标签文字统一引用第 2 节胶囊规则 `13px`、常规字重。文字色与边框色完全一致，背景使用对应的极浅语义色。
- 同一页面中的所有状态类胶囊必须保持相同尺寸、字体、描边、圆角和对齐方式；长状态不得通过改变高度、字号或圆角解决。

## 8. 侧栏信息模块

### 两种工作台字号

## 13. 审核意见通用设计与前端实现规范

本节适用于项目申请、项目修订、进展报告、结项报告等具有“审核页填写意见、修改页查看意见”流程的页面。后续新增字段或模块必须复用同一套数据契约、交互和视觉状态，不得为单个页面另建不兼容的审核意见结构。

### 13.1 页面职责与状态流转

- 审核页负责新增、修改和删除审核意见。可填写审核意见的内容必须提供鼠标与键盘入口，并复用统一审核意见弹窗。
- 修改申请页负责读取和查看审核意见，不直接编辑审核意见。字段、富文本或表格行存在有效意见时自动标红；点击对应标题或行查看具体意见。
- 普通查看页不显示添加入口、指针手势、键盘按钮角色或标红状态，除非产品明确要求展示历史意见。
- 审核意见以接口 JSON 为唯一业务数据源。页面本地状态只能作为尚未提交的编辑副本；提交审核时将完整 `reviewComments` 回写给后端。
- 有效审核意见定义为 `typeof value === 'string' && value.trim().length > 0`。空字符串、纯空白、`null` 和不存在的键均按“无审核意见”处理。
- 删除意见时应删除对应 JSON 键，不保留空字符串占位。Vue 2.6 中使用 `this.$delete`，新增或修改使用 `this.$set`，确保响应式更新。

### 13.2 JSON 数据契约

项目及报告统一在业务 JSON 顶层使用 `reviewComments` 对象。对象键标识被审核内容，值为审核意见正文：

```json
{
  "reviewComments": {
    "name": "请核对项目名称与招募方向是否一致。",
    "overview": "请补充受益范围和社区参与方式。",
    "areas.areas-1": "请核实实施区域与活动地点的一致性。",
    "team.team-2": "请补充该成员的具体职责边界。",
    "stakeholders.stakeholders-1": "请补充相关方参与机制。",
    "outputs.output-1": "请量化产出及验收依据。",
    "activities.activity-1-2": "请补充活动执行人员分工。"
  }
}
```

- 普通字段和富文本使用稳定字段键，例如 `name`、`targets`、`executionPeriod`、`overview`、`background`、`goal`、`experience`。
- 表格整行意见使用 `<集合键>.<稳定行 ID>`，例如 `areas.areas-1`、`team.team-2`、`risks.risk-1`。严禁使用数组下标作为持久化键，避免增删或排序后意见错位。
- 需要精确到单元格时，可使用 `<集合键>.<稳定行 ID>.<字段键>`，例如 `areas.areas-1.province`。修改页判断整行是否标红时，必须同时检查行键本身及该行所有子字段键。
- 项目产出与活动沿用 `outputs.<outputId>` 和 `activities.<activityId>`，活动 ID 在项目内必须唯一。
- 后端返回的 `reviewComments` 应与默认空对象合并，不能覆盖或丢弃未知但合法的键；前端提交时保持相同键格式。
- 前端展示前对值执行 `trim()`，但不得擅自改写审核意见正文、拼接展示文案或将演示意见写入真实提交数据。

### 13.3 字段级审核意见

适用于项目基本信息、报告基本信息及其他标签—内容型字段。

- 审核页：点击整个字段内容块添加或编辑意见；设置 `role="button"`、`tabindex="0"`，同时支持 `Enter` 和 `Space`。
- 修改页：存在意见时字段容器整体标红；点击字段小标题查看意见。优先复用 `ReviewCommentLabel`，无意见时输出普通文本，不生成空弹层。
- 非回写字段不得伪装成审核入口。例如由招募配置固定带入且修改页无法编辑的项目类型、策略、议题等字段，应保持只读。
- 项目基本信息当前可回写键包括：`name`、`targets`、`organization`、`thirdParties`、`executionPeriod`、`rural`、`aid`、`beneficiaries`、`publicBenefit`、`total`、`requested`、`matching`、`leader`、`phone`。
- 审核页模块提示使用“点击字段内容可添加审核意见”。修改页仅在模块至少存在一条有效意见时显示“请检查并修改标红的项目信息，点击信息小标题可查看具体审核意见”。

### 13.4 富文本审核意见

适用于项目概述、项目背景、项目总目标、团队或成员项目管理执行经验等大段内容。

- JSON 键统一为 `overview`、`background`、`goal`、`experience`；新增富文本字段应使用其稳定业务字段名。
- 审核页仅把信息小标题设为添加或编辑入口，正文保持正常阅读和文本选择能力；标题入口必须支持清晰的悬停与键盘焦点状态。
- 存在意见时标红完整正文编辑区或正文展示区，不只标红标题。修改页点击信息小标题查看具体意见。
- 富文本模块存在任意有效意见时才显示提示；无意见时不得显示提示或保留空白占位。
- 附加信息提示统一为“请检查并修改标红的项目信息，点击信息小标题可查看具体审核意见”；执行团队同时包含成员表格时使用“请检查并修改标红的项目信息，点击信息小标题或行任意位置可查看具体审核意见”。审核页将“查看”改为“添加”。

### 13.5 表格行级审核意见

适用于项目实施区域、执行团队、项目相关方、项目风险、监测评估计划等明细表格。

- 审核页点击数据行任意非操作区域新增或编辑整行意见；整行设置按钮角色、键盘焦点及 `Enter`/`Space` 交互。
- 操作列中的编辑、删除、下载、菜单等按钮必须使用 `@click.stop` 和 `@keydown.stop`，不得误触发行级审核弹窗。
- 新增空白行、汇总行和无稳定业务 ID 的演示行不提供审核入口。
- 修改页仅当该行或该行任一单元格存在意见时设置 `review-row-has-comment`；点击整行查看合并后的具体意见。存在多条单元格意见时按字段顺序展示，不得静默丢弃。
- 模块存在任意有效意见时才显示提示。项目实施区域和项目管理计划统一使用“请检查并修改标红的项目信息，点击行任意位置可查看具体审核意见”；执行团队按上一节的组合提示处理。

### 13.6 审核意见弹窗

- 字段、富文本和表格行统一复用一个审核意见弹窗，不为不同模块建立视觉不一致的弹窗。
- 弹窗标题统一为“编辑审核意见”。项目审核、进展/结项审核和募捐申请审核统一沿用项目审核尺寸：宽度 `560px`，多行文本框默认 `5` 行；正文只显示审核意见输入框，不添加字段或内容小标题、说明段落。其他业务审核弹窗沿用各自既定尺寸，未明确要求时不批量调整历史页面。
- 上述三类审核弹窗根据当前 JSON 键是否存在有效审核意见区分操作状态，不根据尚未保存的输入内容切换按钮。无意见时不显示删除按钮，底部右侧按“取消、确认”排列；有意见时底部左侧显示红色“删除”，右侧仅显示主操作“修改”。使用 `flex` 保持左右操作分组，右侧按钮间距 `8px`；“确认”和“修改”均调用现有保存逻辑。“取消”关闭弹窗且不写入 JSON。

- 原型阶段未接后端时必须明确属于本地演示，不得提示“已提交服务器”。

### 13.8 Vue 2.6 实现约定

- 使用 Options API、`computed` 和 `methods`；不得使用 Vue 3 `setup` 或 Composition API。
- 将审核意见读取、有效性判断、样式判断和行前缀匹配集中为公共方法，避免在模板内散落不同判断。
- 使用 `ReviewCommentLabel` 展示字段或小标题意见；行级意见可复用统一 Popover 或统一详情弹窗。
- 审核模式下才添加按钮角色和事件；普通查看模式返回空样式对象并直接退出事件方法。
- 推荐的最小读取逻辑如下：

```js
reviewComment (key) {
  const value = (this.reviewComments || {})[key]
  return typeof value === 'string' ? value.trim() : ''
},
rowReviewComment (sectionKey, rowId, fieldKeys = []) {
  const prefix = `${sectionKey}.${rowId}`
  const knownKeys = fieldKeys.map(key => prefix + '.' + key)
  const extraKeys = Object.keys(this.reviewComments || {})
    .filter(key => key.indexOf(prefix + '.') === 0 && !knownKeys.includes(key))
    .sort()
  return [prefix].concat(knownKeys, extraKeys)
    .map(key => this.reviewComment(key))
    .filter(Boolean)
    .join('\n')
},
saveReviewComment (key, value) {
  const text = typeof value === 'string' ? value.trim() : ''
  if (text) this.$set(this.reviewComments, key, text)
  else this.$delete(this.reviewComments, key)
}
```

- 调用行级读取方法时，按表格显示顺序传入 `fieldKeys`；合并展示整行意见及所有有效单元格意见，未知字段键追加展示。该拼接仅用于展示，不回写到原始意见正文。
- 修改页加载数据时使用 `{ ...defaults.reviewComments, ...(payload.reviewComments || {}) }` 合并，确保新增键可直接生效。
- `reviewComments` 的对象引用必须保持响应式；接口返回后整体替换时使用新对象，局部增删时使用 `$set`/`$delete`。
- 页面提交或保存草稿时将 `reviewComments` 与业务表单 JSON 一并提交，不建立只存在于 DOM、组件内部或 CSS 中的意见状态。

### 13.9 人工验收清单

- 项目、进展/结项和募捐申请审核弹窗均为 `560px`、默认 `5` 行输入框，正文无小标题；无意见时右侧显示“取消、确认”，有意见时左侧“删除”、右侧“修改”。输入过程中按钮状态不变化；取消后原 JSON 不变，确认/修改后重新打开能回显，删除后再次打开恢复无意见按钮。
- 审核页的可回写字段、富文本小标题和所有有效数据行均能通过鼠标、Enter 和 Space 打开意见弹窗。

- 表格排序、插入和删除行后，审核意见仍跟随稳定行 ID，不串行、不丢失。
- 模块无有效意见时不显示修改提示；有任意有效意见时显示与模块交互方式匹配的提示文案。
- 长意见、换行、连续英文或数字在弹层中完整换行，不溢出；遮罩点击不能关闭编辑弹窗。
- 修改申请页只允许查看审核意见，不意外改写意见；保存业务内容时原有 `reviewComments` 不被清空。

- 人力成本分摊表：`src/views/ProjectPersonnelForm.vue` 独立编辑页与项目申请审核/查看页的人力页签统一复用 `src/components/ProjectPersonnelTable.vue`；`BudgetPrototype.vue` 仅负责页签容器和传入预算 JSON。
- 报告、筹款规划的预算预览及其他预算页签保留各自实现。本节不授权批量修改，也不将预算表格专项尺寸推广到普通业务表格；费用及人员录入弹窗按第 15.7 节处理。

### 15.2 字体、单元格与对齐

| 项目 | 预算明细表及人力表规则 |
| --- | --- |
| 表内字号 | 统一 `13px`，使用 `var(--text-13)`；含表内项目名称、表名、表头、正文、金额、备注、文字链接和预算明细表内添加按钮 |
| 字体与行高 | 沿用第 2 节字体栈；行高 `1.4`；表头及合计、分组的既定加粗保留，不通过增大字号强调 |

- 表外项目名称沿用 `16px / 700`，项目编号、状态和底部操作按钮沿用 `14px`。
- 预算明细表的分期及合计金额使用内容容器 `min-height: 23px; line-height: 20px`，保留此内部对齐规则。人力表金额使用 `font-variant-numeric: tabular-nums`。

### 15.3 预算明细表尺寸与颜色

- 按 `budgetColumns` 的 15 列顺序，最低列宽为 `[90, 120, 210, 80, 80, 80, 80, 80, 100, 100, 60, 210, 100, 100, 60]px`，不按容器比例拉伸。四期预算、合计、预算调整金额、调整后预算、执行金额均使用 `measureBudgetWidths` 测量实际格式化金额，兼顾常规/加粗字重和千分位，在最低宽度上增宽；表宽为列宽总和。编辑、审核、查看共用计算方式。
- 审核/查看表位于可横向滚动容器，空间不足时左右滚动，不压缩列宽。独立编辑页按实际表宽设置页面最小宽度。

| 区域 | 样式 |
| --- | --- |
| 表名、列标题背景 | `#F2F2F2` |
| 合计行 | `#FFE3E7`，加粗 |
| 费用分组、产出行 | `#EDFFCE`，加粗 |
| 产出活动行 | `#D4F2FF` |
| 费用明细行 | 白底 |

- 编辑模式：分期和合计金额基准色 `#02A7F0`，费用明细行分期金额为 `#70B603`，合计金额列仍为蓝色；可编辑科目使用 `#F59A23` 下划线文字链接。
- 审核/查看模式：全部金额为黑色 `#000`，保留各区域底色；科目为只读正文，不显示编辑入口和添加费用/编辑人力等操作行。

### 15.4 明细内容与数据展示

- 单价和金额显示两位小数；数量统一两位小数，有单位量词时紧随数量，如“100.00元 × 4.50只”。
- 单价 × 数量与明细说明分成独立块，说明设置 `margin: 8px 0 0`，不以两个换行符模拟块间距。旧合并文本通过 `budgetDetailParts` 仅作展示适配，不反写推测的原始单价、数量或单位。
- 单价及数量必须大于 0，最多两位小数；单条明细的单价 × 数量须等于四期金额之和。金额范围及其余业务校验复用 `validateCost`、`validateCostValues`，不在页面另建一套规则。
- 活动无需预算时可不添加费用；保留产出和活动行，不生成“无”或零单价的占位预算明细行。旧占位记录可保留在 JSON 的兼容字段中，不静默删除原数据。
- 编辑时通过 `snapshotBudget` 把表头业务资料、产出活动的稳定 ID/编号/名称及非计算明细写入 `project.budget`。审核/查看只读预算自己的 `metadata`、`groups`、`rows`、`personnel`，不从当前项目信息补值；合计和比例由原始金额计算。缺失调整/执行数据显示“/”，缺失单价不伪造为 0。

### 15.5 人力成本分摊表专项尺寸与颜色

- 编辑、审核、查看表宽均为 `1550px`，12 列宽依次为 `[120, 100, 100, 400, 110, 100, 100, 100, 110, 110, 110, 90]px`。独立编辑页最小宽度 `1592px`；审核/查看表位于横向滚动容器，空间不足时滚动，不压缩列宽。人力表仍保留固定列宽，不将预算明细表的金额自适应规则声明为此表已实现。
- 表名和列标题背景 `#F2F2F2`；总计行背景 `#EDFFCE`，总计金额加粗。编辑模式的月人力成本、月份数为绿色 `#70B603`，人力占比及人力成本总额为蓝色 `#02A7F0`；姓名编辑入口为橙色 `#F59A23` 下划线，继承表内 `13px`。
- 审核/查看模式：姓名为只读正文，无编辑入口；金额、占比和月份数使用黑色 `#000`，保留表头及总计行底色。执行额、预算调整金额、调整后预算继续读取预算 JSON，缺失时显示“/”；人力成本总额和总计复用 `personnelAmount` 与原汇总方式，不在查看时从当前执行团队补数据。
- 人力成本分摊表的“备注”仅允许“专职”或“兼职”，录入使用既有下拉选项，人员校验及保存同时限制取值；示例 JSON 遵循同一规则，不将分摊计算说明写入备注。专职/兼职不能仅由本项目人力占比推断。
- 底部按钮居中、间隔 `12px`、最小宽度 `100px`；底部操作栏沿用粘滞定位和白底。

### 15.7 预算编辑录入弹窗

- 适用范围仅为 BudgetCostModal.vue 的添加/编辑支撑费用、活动预算，以及 PersonnelBudgetModal.vue 的编辑人员预算。复用第 7 节标准表单弹窗和第 14 节输入/只读文本规则；其他历史弹窗不据此批量修改。
- 两个组件均通过 wrap-class-name 接入 standard-form-modal、standard-edit-scope、standard-edit-modal；下拉浮层显式使用 standard-edit-dropdown。公共布局入口为 src/styles/common.css 中的 budget-modal-form，不在组件中重复固定标签列宽或公共字号。
- 宽度 550px，内容宽 470px、水平居中；标题区及底部区各 55px，正文上下留白 32px。表单使用共享标签列，自然宽度、最大 140px，标签右对齐，列间距 18px、行间距 16px。标签和普通按钮 14px；可编辑内容、输入提示及下拉选项 16px，单行控件高 40px，保留数值/选择器内部 38px 行高。

- 姓名、职务、工作内容、产出活动上下文及已计算金额使用无边框、无底色的纯文本，文字色 #27384e、14px、字重 500、行高 1.6，保留换行，不用禁用输入框模拟。相应标签行取消控件对齐所需的上内边距及最小高度；未计算时的输入提示使用 16px、#5b8ff9。
