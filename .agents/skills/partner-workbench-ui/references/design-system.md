# 伙伴端工作台设计约束

本规范维护伙伴端页面的视觉、交互和审核意见契约。原型决定产品内容与模块结构；通用视觉遵循本规范，用户明确指定的例外优先。现有实现不自动覆盖规范。

阅读导航：基础视觉与布局见第 1–5 节；列表、状态和操作见第 6–7 节；特殊工作台模块见第 8–9 节；原型与人工验收见第 10–11 节；报告详情及警示弹窗见第 12 节；审核意见见第 13 节；填写页提示、日期及成果入口见第 14 节。第 13 节编号保持稳定，供 `AGENTS.md` 引用。

实现参考：`src/layouts/PartnerLayout.vue`、`src/views/Dashboard.vue`、`src/styles/common.css` 提供工作台骨架；`src/views/ProjectForm.vue`、`src/views/ReportForm.vue` 提供填写页；`src/views/ReportDetail.vue` 提供报告详情。修改前核对实际代码及当前需求，不直接照搬历史差异。

## 1. 设计基调

- 定位：桌面端项目管理后台，信息密度中等，强调清晰、可信和轻量现代感。
- 页面骨架：深海军蓝固定侧栏、半透明白色固定顶栏、冷灰蓝页面底色、白色内容卡片。
- 品牌色以蓝色表达主要操作和当前导航，以绿色表达生态、品牌和正向进度。
- 装饰克制：常规卡片使用细描边、16px 圆角和浅阴影；渐变只用于品牌标识、激活导航、特定封面及独立功能入口。
- 不使用大面积高饱和色填充正文区域，也不为普通业务模块引入紫色 AI 视觉语言。

## 2. 基础令牌

### 字体

- 字体栈：`Inter, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 正文字号：`10pt`（约 13.33px）；主要标题及卡片条目标题：`12pt`（16px）。
- 正文常规字重；页面品牌、模块标题、关键名称使用 `600–700`。
- 正文说明行高约 `1.55–1.65`。辅助信息使用弱化颜色，不通过过小字号堆叠信息。

### 核心颜色

| 角色 | 色值 |
| --- | --- |
| 页面背景 | `#f4f7fb` |
| 主文字 | `#18253c` |
| 次级文字 | `#718095` |
| 主操作蓝 | `#1677ff` |
| 输入提醒蓝 | `#5b8ff9` |
| 品牌绿 | `#18a66a` / `#18b875` |
| 通用边框 | `#e6ebf2` |
| 内容分隔线 | `#edf1f5` |
| 深色侧栏 | `linear-gradient(180deg, #061a30, #0a2c4b)` |

### 间距、圆角和阴影

- 页面左右内边距：28px；内容顶部 20px；页面底部保留 64px。
- 主栏与侧栏间距：24px；主栏卡片间距：20px；侧栏卡片间距：18px。
- 普通卡片：`border: 1px solid #e6ebf2`、`border-radius: 16px`、`box-shadow: 0 4px 18px rgba(23,56,92,.05)`。
- 卡片标题栏左右内边距 20px；主栏标题栏最小高度 64px，侧栏标题栏最小高度 56px。
- 列表内容通常使用 20–22px 内边距和 20px 列间距。
- 所有列表中的项目图片统一固定为 **80×80px、13px 圆角**，包括伙伴工作台、SEE 工作台待办和已申请项目列表。实际图片与图标占位封面均使用相同尺寸及圆角；容器禁止收缩并设置 `overflow: hidden`，图片填满容器并使用 `object-fit: cover`。新增列表必须遵循此规范，原型中的旧尺寸或圆角示例不得覆盖该标准；仅在用户明确要求例外时调整。

## 3. 页面骨架与响应式

- 默认桌面布局预留 256px 固定侧栏和 72px 固定顶栏。
- 工作台内容采用双栏：左侧主内容 `minmax(740px, 1fr)`，右侧信息栏固定 400px，间距 24px；内容网格最小宽度 1164px。
- 右侧信息栏在宽、高足够时从顶栏下方粘滞显示，顶部偏移 92px。
- 视口不超过 1600px 时，侧栏缩至 220px，推荐卡由三列改为两列，页面维持至少 1280px 的桌面工作区。
- 视口不超过 1366px 时，侧栏折叠为 72px，仅保留图标；品牌文字、导航文字、箭头和子菜单隐藏。新增导航必须提供可理解的图标与 `title`。
- 不把当前伙伴端改造成移动端卡片流，除非原型或需求明确要求移动适配。

## 4. 导航与顶栏

- 页面级返回按钮统一固定悬浮在内容区右上方，文案统一为“返回”，搭配 `arrow-left` 图标。按钮使用 `position: fixed`，桌面端定位为 `top: 92px; right: 28px`，位于 72px 固定顶栏下方并与内容区 20px 顶部间距对齐；层级低于顶栏、高于正文，页面滚动时持续可见。
- 复用 `detail-back-row` 与 `detail-back` 公共样式；原按钮容器至少保留 `38px` 高度作为布局占位，防止按钮脱离文档流后首个内容模块上移。报告详情等使用独立标题行的页面也应保留等高占位。
- 返回目标、未保存提醒及禁用逻辑沿用各页面既定行为。在 1920px、1440px、1366px 以及出现横向滚动的窄桌面视口下，人工确认按钮不与顶栏、垂直滚动条、底部固定操作栏或弹窗重叠。

- 一级导航高度 48px、圆角 11px，图标与文字间距 12px；默认文字 `#b9c8d7`。
- 悬停使用低透明白色背景；激活项使用 `#1677ff → #4597ff` 横向渐变、白字和轻蓝阴影。
- 子导航高度 40px，左侧缩进约 46px；激活态用半透明主蓝背景。
- 退出入口固定在导航底部语义位置，使用危险红 `#ff6b76`，与普通导航分隔。
- 顶栏高 72px、左右内边距 28px；左侧面包屑，右侧通知、分隔线及用户信息。图标型按钮保持约 40×40px 的稳定点击区域。

## 5. 卡片与模块标题

- 卡片保持白底、细边框和浅阴影，不在同一页面混用明显不同的圆角体系。
- 主模块标题使用 16px、700 字重，标题前可放 4×20px 圆角竖条区分业务模块。
- 已有竖条语义：进行中项目为绿色；募捐申请为紫色渐变；招募推荐为橙色；最新招募为蓝色。相同模块沿用相同颜色。
- 侧栏标题使用 Ant Design 图标，不再添加竖条；系统通知为金色、机构信息为青绿、常见问题为蓝色、制度文件为靛蓝色。
- 标题栏右侧的“查看全部”、搜索和筛选保持右对齐，不挤压标题。
- 项目填写页模块标题下方的审核意见交互提示必须由该模块的审核意见数据控制：仅当模块内至少存在一条有效审核意见时显示；没有审核意见时不显示提示文案，也不保留空白占位或使用普通说明文案替代。

## 6. 列表、信息层级与长内容

- 列表以细分隔线分组，最后一项不显示底部分隔线。
- 标准业务条目按“80px 缩略图 / 自适应正文 / 可选操作区”组织；正文容器必须设置 `min-width: 0`。
- 各个列表中的项目名称必须完整显示，超长时自动换行。适用于伙伴工作台、SEE 工作台、已申请项目、进展/结项及后续新增列表，包括可点击的项目名称。使用 `min-width: 0; white-space: normal; overflow-wrap: anywhere` 和约 `1.5–1.6` 行高；禁止省略号截断、行数限制或固定高度裁剪，不得仅靠悬停提示展示完整名称。行高随内容自然撑开，状态、日期和操作区保留各自空间，不得被长名称挤压或遮挡。
- 已申请项目、进展/结项等桌面数据列表以 `1440px` 视口宽度作为完整展示基准：`1440px` 及以上不应出现表格横向滚动，低于 `1440px` 时允许横向滚动。项目类型、状态胶囊、筹款状态、两行日期时间、成果指标和操作等内容稳定的列，按实际内容设置最小固定宽度；扣除选择列和固定列后的剩余宽度优先分配给项目名称列。不得通过省略、裁剪项目名称来换取无横向滚动。实现时需同时考虑 `1366px` 侧栏折叠造成的内容区宽度变化，确保滚动触发标准不因侧栏折叠失效。
- 录入型业务明细表格统一将“序号”列固定为 `70px`、“操作”列固定为 `130px`，两列均按可完整容纳表头和常用操作的最小值设置，不随表格宽度按比例扩张。省市区、人员、风险、监测等同类录入表格使用相同参数；其余内容列分配剩余宽度，内容较长时自然换行。该规则不覆盖项目列表中下拉操作列的 `85px` 专用规范。
- 描述使用次级文字色与 1.55 左右行高；项目多段描述可使用 `white-space: pre-line`。
- 时间、联系方式、项目组等元信息优先使用图标加文本；允许换行，但同类元信息的颜色与间距必须一致。
- 逾期行使用由 `#fff3bf` 过渡到近白色的浅黄色背景，并显示金色警示文字；不要仅依赖背景色传达逾期。

### 项目列表业务标识

项目列表中的项目编号、机构名称和招募名称是三种固定业务语义，必须使用各自的图标与颜色，不得互换或统一成普通次级文字。

- 布局：项目标题单独占第一行；标题与下一行标识之间保留约 `10px` 的视觉间距。项目编号与机构名称位于第二行，使用 `flex` 横排并保持 `8px` 间距；招募名称位于第三行。
- 通用外观：标识采用“图标 + 文本”，内边距 `2px 7px`、圆角 `3px`，文字保持正文常规字重。正文容器必须设置 `min-width: 0`，不得挤压状态、日期或操作列。
- 项目编号：使用 `flag` 图标，文字色 `#62BFE6`，背景色 `#EFFAFF`。该样式仅表示项目编号，例如 `ZZ-1764740216`。
- 报告编码：在报告详情的“项目基本信息”模块标题格内，紧跟项目编码展示；使用 `file-text` 图标，文字色 `#5B8FF9`，背景色 `#F0F5FF`，内边距 `2px 7px`、圆角 `3px`。该样式仅表示进展/结项报告编码，例如 `P-001006`。
- 机构名称：使用 `bank` 图标，文字色 `#61BD98`，背景色 `#F1FBF5`。该样式仅表示项目所属或申报机构。
- 招募名称：使用 `notification` 图标，文字色 `#B081D0`，背景色 `#FAF4FF`；悬停时文字色 `#9360B8`、背景色 `#F5EAFF`。招募名称是可打开招募详情的入口，长文本应在项目名称列内自然换行并完整展示，不使用省略号截断。
- 三类标识的颜色必须同时配合图标和文本表达含义，不能只依靠底色区分。

## 7. 状态与操作

### 状态标签

状态类胶囊配色以用户确认的工作台与项目列表样式为强制规范，适用于项目状态、募捐申请状态等业务状态。新页面只要展示状态，就必须复用本节样式，不得使用 Ant Design 预设标签色、旧页面近似色或自行扩展的渐变色替代。

- 标签统一为 `112px × 24px`，`box-sizing: border-box`，1px 实线边框，`5px` 圆角；文字水平和垂直居中、单行不换行。“募捐申请通过”胶囊的圆角为统一基准。
- 标签文字使用约 14px 常规字重。文字色与边框色完全一致，背景使用对应的极浅语义色。
- 同一页面中的所有状态类胶囊必须保持相同尺寸、字体、描边、圆角和对齐方式；长状态不得通过改变高度、字号或圆角解决。

| 状态分组 | 适用状态 | 文字与边框 | 背景 |
| --- | --- | --- | --- |
| 灰色中性 | 草稿、审核流程中①、申请待定、待筹款修订（中性等待）、已结项 | `#7F7F7F` | `#F2F2F2` |
| 橙色待审 | 募捐申请待审、申请待审、筹款修订待审、进展待审、结项待审、请求修订、修订待审、补充结项待审 | `#FA8C16` | `#FFF7E6` |
| 绿色执行/通过 | 执行中、进展已审、结项已审 | `#70B603` | `#F8FFED` |
| 红色修改/驳回 | 募捐申请驳回、申请待修改、待筹款修订（需处理）、筹款修订驳回、进展驳回、结项驳回、修订中、修订驳回、补充结项驳回 | `#FF4D4F` | `#FFF1F0` |
| 青色通过 | 募捐申请通过 | `#13A8A8` | `#E6FFFB` |

“募捐申请待审”是橙色待审类的配色基准；“募捐申请驳回”是所有驳回、退回修改和异常处理类状态的红色配色基准；“募捐申请通过”是青色通过类及统一 `5px` 圆角的外观基准。跨页面使用这些语义时必须采用表中精确色值。

“待筹款修订”在标准图中存在两种业务语义：仅表示中性等待时使用灰色；表示当前需要用户处理或异常提醒时使用红色。实现时必须依据状态字段或业务上下文区分，不能只用显示文案决定颜色；上下文不明确时保留原型指定颜色并标记待人工确认。

建议集中维护状态到样式角色的映射（例如 `neutral`、`pending-review`、`active-approved`、`action-rejected`），所有页面复用同一组 CSS 类，避免在组件内散落色值。附件中的黄色数字 `1`、`2` 是原型批注标记，不属于状态内容，成品中不得显示。

未列出的新状态不得自行选择颜色。先根据明确业务含义归入上述五组；无法确认时请求人工确认。颜色必须与状态文字共同表达含义，不能只依靠颜色传达状态。

### 按钮

- 优先使用 Ant Design Vue 1.7.8 的 `a-button`，再通过语义类调整颜色。
- 已申请项目、进展/结项等数据列表的固定操作列统一为 `85px`；下拉操作入口使用无边框、透明背景的轻量文字按钮并水平居中。按钮文案与下拉箭头间距固定为 `2px`，同时覆盖 Ant Design Vue 默认的相邻图标 `margin-left: 8px`，避免间距叠加。相同列表入口不得自行设置不同的操作列宽度或箭头间距。
- 本节颜色规范中列出的所有业务操作按钮统一固定高度为 `32px`，不得因按钮文案、业务类型或所在模块设置不同高度；胶囊按钮使用 `border-radius: 999px`，最小宽度约 108px。导航按钮、纯图标按钮和分页控件按各自组件规范执行。
- 所有业务操作按钮统一使用轻量底部阴影 `box-shadow: 0 2px 0 rgba(0,0,0,.043)`；默认、悬停、聚焦及按下状态不得因 Ant Design 按钮类型不同而出现深浅不一致。
- 操作按钮严格使用下表中的文案、图标和颜色映射。相同文案若因业务状态需要灰色或红色，须由明确状态语义决定，不得使用近似色替代。

| 色彩角色 | 色值 | 对应操作 | Ant Design 图标 |
| --- | --- | --- | --- |
| 灰色常规编辑 | `#7F7F7F` | 编辑草稿、修改申请、请求修订 | `edit`、`edit`、`file-exclamation` |
| 红色退回修订 | `#D9001B` | 修改申请、募款修订、重新修订、项目修订、修改进展、修改结项 | 前四项 `edit`；修改进展 `form`；修改结项 `book` |
| 橙色进展提交 | `#F59A23` | 提交进展 | `container` |
| 绿色结项/填表 | `#70B603` | 提交结项、上传填表 | `book`、`flag` |
| 青绿色项目申请 | `#5AC7B0` | 申请项目 | `file-add` |
| 浅蓝色募捐申请 | `#81D3F8` | 募捐申请 | `file-add` |

- 彩色实心按钮悬停或聚焦时切换为白底、保留同色文字和边框。点击区域、图标对齐和反馈行为必须一致。
- 搜索等标准主操作沿用 Ant Design 主蓝，不套用业务状态色。

### 表单弹窗

- 填写页的提示字号与颜色遵循第 14 节。
- 项目申请填写页的标准录入弹窗统一使用 `550px` 宽度，当前包括项目实施区域、执行团队、增加或编辑产出、增加或编辑活动；同一业务对象的新增态与编辑态必须保持相同宽度。
- 弹窗内容按既定表单栅格和字段顺序自然排布，不得通过放大同类弹窗宽度掩盖字段对齐或间距问题。桌面视口不足时沿用 Ant Design Vue 的安全边距与自适应行为，不设置超出视口的固定最小宽度。
- 附件预览、复杂名单选择、审核警示等具有不同信息密度或专项交互的弹窗，不强制套用 `550px`；优先遵循对应模块的既有实现或本规范中的专项规则。
- 所有新增或修改的模态弹窗默认禁止点击遮罩关闭：`a-modal` 显式设置 `:mask-closable="false"`，命令式 Modal 设置 `maskClosable: false`，自定义模态弹窗遵循相同规则。关闭图标、Esc、确定、取消等沿用既定行为；用户明确要求的例外优先。

## 8. 侧栏信息模块

- 系统通知是例外强调卡：背景 `#fff8df`、边框 `#f0dfaa`、金色图标；悬停可加深至 `#fff2c2`。
- 机构信息保持“机构身份 / 三列数据 / 联系方式 / 最近登录”的层级；三列统计共享一个圆角描边容器并用竖线分隔。
- 常见问题和制度文件使用约 46px 高的整行入口；内容行左侧直接显示省略文本，不放置图标，右侧保留箭头；悬停背景 `#f8fbff`。模块标题中的语义图标仍保留。
- 不为了减少侧栏高度删掉信息模块；通过合理间距、粘滞区域或滚动策略处理。

## 9. 推荐卡与特殊功能

- 推荐卡使用 14px 圆角、细边框和上图下文结构；图片区域约高 118px，正文内边距 13px。
- 不同生态主题可以使用自然色渐变，但饱和度保持克制，并确保白色图标可读。
- AI 助手可使用独立的紫色科技感系统（紫色渐变、微弱网格和青色点缀），但必须封装在 AI 入口和对话面板内。
- AI 对话面板当前基准宽 420px、圆角 20px；消息区浅紫白背景，助手白色气泡，用户紫色渐变气泡。不要将这种气泡和霓虹装饰复制到普通业务卡片。

## 10. 原型清理规则

以下内容可以存在于设计稿或原型说明层，但不得出现在成品页面，除非它本身就是明确的产品功能：

- “尺寸示例”“按钮样式”“状态样式”等组件标注或全集展示。
- 标尺、像素尺寸、参考线、布局网格说明和设计备注。
- 为说明极端情况而写的“超长时的样式”“这里是名称”“第一行内容”等示例性文案；成品展示应替换为自然、可信的业务数据。
- “纯视觉换肤提案”“保留原型全部元素”等设计交付说明和页脚注释。

清理演示内容不等于删除功能。对应的正式模块、字段、状态和操作入口仍须完整保留。

## 11. 人工验收清单

- 原型中的所有功能、标题、模块、字段、状态和按钮均可找到。
- 页面内不存在尺寸标注、样式枚举、参考线或设计说明。
- 侧栏、顶栏、主次栏宽度及卡片节奏与当前工作台一致。
- 普通、悬停、激活、禁用、待审、成功、驳回和逾期等实际需要的状态可辨识。
- 各列表长项目名称完整显示并自动换行（含连续英文或数字），无省略号、行数限制或裁剪；换行后状态、日期及操作按钮不被遮挡。长描述、空数据和多操作按钮不会溢出或互相遮挡。
- 在 1920px、1440px 和 1366px 桌面宽度下人工查看关键页面；1366px 检查折叠侧栏的图标及提示。
- 所有可点击元素具有合理反馈，纯展示交互不会冒充真实后端成功。

## 12. 进展/结项详情与警示弹窗

### 进展/结项详情

- 进展/结项详情不额外展示页面级报告标题和章节导航；从隐私提示直接进入“项目基本信息”模块，避免与模块标题重复。
- 基本信息模块标题使用报告类型（例如“进展报告（需要请款）”）；第二行按“项目编号、报告编号”排列。报告编号必须使用本规范第 6 节的 `file-text` 蓝色标识样式。项目周期字段统一命名为“项目执行周期”。
- “产出衡量标准”使用橙色标签和主文字内容，内容可为多段；标签与正文顶部对齐，不单独添加横向分隔线。
- “产出执行进展”使用左侧浅蓝标签、右侧进展列表的两列布局；不使用外边框、底色卡片、圆点或时间线。时间与内容使用 14px 主文字色、顶部对齐并支持自然换行；相邻记录用 `#edf1f5` 细线分隔，最新记录的时间和内容统一使用主操作蓝 `#1677ff`。
- 活动信息保留活动编号和名称、时间/地点/执行人员及活动内容。活动内容使用主文字色 `#18253c`。活动执行进展使用无外边框、无底色的两列表格，左列为固定宽度时间、右列为可换行内容；相邻记录使用 `#edf1f5` 分隔，标题和最新记录使用品牌绿 `#18a66a`，不使用时间线。
- 在线预算表与附件沿用项目申请审核页的嵌入式预算表和附件列表样式，不使用报告详情中的独立宽表格。审核信息置于审核操作模块上方，时间与审核账号合并为一个浅色信息块显示。
- 所有项目申请、进展报告和结项报告的审核操作模块统一使用淡红色审核面板：容器背景 `#fff6f6`、边框 `#f1dede`；标题栏背景 `#ffd9d9`、底部分隔 `#efbaba`，审核图标使用红色文字和白色底。表单内容区保持白色，避免影响字段可读性。

### 审核阻断警示弹窗

- 请款状态与实际金额不一致等可修正但会阻断审核的校验，使用简洁无分割线弹窗；使用 Ant Design Vue 1.7.x `a-modal`，必须设置 `:mask-closable="false"`。
- 弹窗不使用默认标题栏、页脚或右上角关闭图标；设置 `:footer="null"`、`:closable="false"`，仅保留内容区右下角“关闭”按钮作为关闭入口。
- 内容区采用单一白色容器：顶部内边距 36px，左右及底部内边距 28px。错误图标（`close-circle`、`#ff4d4f`、22px）与 16px/700 的标题使用同一行 `flex` 并垂直居中，间距 12px；说明文案使用 `#718095`、1.7 行高，并与标题文字左侧对齐。
- “关闭”按钮沿用主操作蓝，固定高度 32px、轻量底部阴影，右对齐；遮罩不可关闭，避免审核表单输入被误操作丢失。

## 13. 审核意见通用设计与前端实现规范

本节适用于项目申请、项目修订、进展报告、结项报告等具有“审核页填写意见、修改页查看意见”流程的页面。后续新增字段或模块必须复用同一套数据契约、交互和视觉状态，不得为单个页面另建不兼容的审核意见结构。

### 13.1 页面职责与状态流转

- 审核页负责新增、修改和删除审核意见。可填写审核意见的内容必须提供鼠标与键盘入口，并复用统一审核意见弹窗。
- 修改申请页负责读取和查看审核意见，不直接编辑审核意见。字段、富文本或表格行存在有效意见时自动标红；点击对应标题或行查看具体意见。
- 普通查看页不显示添加入口、指针手势、键盘按钮角色或标红状态，除非产品明确要求展示历史意见。
- 审核意见以接口 JSON 为唯一业务数据源。页面本地状态只能作为尚未提交的编辑副本；提交审核时将完整 `reviewComments` 回写给后端。
- 有效审核意见定义为 `typeof value === 'string' && value.trim().length > 0`。空字符串、纯空白、`null` 和不存在的键均按“无审核意见”处理。
- 删除意见时应删除对应 JSON 键，不保留空字符串占位。Vue 2.6 中使用 `this.$delete`，新增或修改使用 `this.$set`，确保响应式更新。

### 13.2 JSON 数据契约

项目及报告统一在业务 JSON 顶层使用 `reviewComments` 对象。对象键标识被审核内容，值为审核意见正文：

```json
{
  "reviewComments": {
    "name": "请核对项目名称与招募方向是否一致。",
    "overview": "请补充受益范围和社区参与方式。",
    "areas.areas-1": "请核实实施区域与活动地点的一致性。",
    "team.team-2": "请补充该成员的具体职责边界。",
    "stakeholders.stakeholders-1": "请补充相关方参与机制。",
    "outputs.output-1": "请量化产出及验收依据。",
    "activities.activity-1-2": "请补充活动执行人员分工。"
  }
}
```

- 普通字段和富文本使用稳定字段键，例如 `name`、`targets`、`executionPeriod`、`overview`、`background`、`goal`、`experience`。
- 表格整行意见使用 `<集合键>.<稳定行 ID>`，例如 `areas.areas-1`、`team.team-2`、`risks.risk-1`。严禁使用数组下标作为持久化键，避免增删或排序后意见错位。
- 需要精确到单元格时，可使用 `<集合键>.<稳定行 ID>.<字段键>`，例如 `areas.areas-1.province`。修改页判断整行是否标红时，必须同时检查行键本身及该行所有子字段键。
- 项目产出与活动沿用 `outputs.<outputId>` 和 `activities.<activityId>`，活动 ID 在项目内必须唯一。
- 后端返回的 `reviewComments` 应与默认空对象合并，不能覆盖或丢弃未知但合法的键；前端提交时保持相同键格式。
- 前端展示前对值执行 `trim()`，但不得擅自改写审核意见正文、拼接展示文案或将演示意见写入真实提交数据。

### 13.3 字段级审核意见

适用于项目基本信息、报告基本信息及其他标签—内容型字段。

- 审核页：点击整个字段内容块添加或编辑意见；设置 `role="button"`、`tabindex="0"`，同时支持 `Enter` 和 `Space`。
- 修改页：存在意见时字段容器整体标红；点击字段小标题查看意见。优先复用 `ReviewCommentLabel`，无意见时输出普通文本，不生成空弹层。
- 非回写字段不得伪装成审核入口。例如由招募配置固定带入且修改页无法编辑的项目类型、策略、议题等字段，应保持只读。
- 项目基本信息当前可回写键包括：`name`、`targets`、`organization`、`thirdParties`、`executionPeriod`、`rural`、`aid`、`beneficiaries`、`publicBenefit`、`total`、`requested`、`matching`、`leader`、`phone`。
- 审核页模块提示使用“点击字段内容可添加审核意见”。修改页仅在模块至少存在一条有效意见时显示“请检查并修改标红的项目信息，点击信息小标题可查看具体审核意见”。

### 13.4 富文本审核意见

适用于项目概述、项目背景、项目总目标、团队或成员项目管理执行经验等大段内容。

- JSON 键统一为 `overview`、`background`、`goal`、`experience`；新增富文本字段应使用其稳定业务字段名。
- 审核页仅把信息小标题设为添加或编辑入口，正文保持正常阅读和文本选择能力；标题入口必须支持清晰的悬停与键盘焦点状态。
- 存在意见时标红完整正文编辑区或正文展示区，不只标红标题。修改页点击信息小标题查看具体意见。
- 富文本模块存在任意有效意见时才显示提示；无意见时不得显示提示或保留空白占位。
- 附加信息提示统一为“请检查并修改标红的项目信息，点击信息小标题可查看具体审核意见”；执行团队同时包含成员表格时使用“请检查并修改标红的项目信息，点击信息小标题或行任意位置可查看具体审核意见”。审核页将“查看”改为“添加”。

### 13.5 表格行级审核意见

适用于项目实施区域、执行团队、项目相关方、项目风险、监测评估计划等明细表格。

- 审核页点击数据行任意非操作区域新增或编辑整行意见；整行设置按钮角色、键盘焦点及 `Enter`/`Space` 交互。
- 操作列中的编辑、删除、下载、菜单等按钮必须使用 `@click.stop` 和 `@keydown.stop`，不得误触发行级审核弹窗。
- 新增空白行、汇总行和无稳定业务 ID 的演示行不提供审核入口。
- 修改页仅当该行或该行任一单元格存在意见时设置 `review-row-has-comment`；点击整行查看合并后的具体意见。存在多条单元格意见时按字段顺序展示，不得静默丢弃。
- 模块存在任意有效意见时才显示提示。项目实施区域和项目管理计划统一使用“请检查并修改标红的项目信息，点击行任意位置可查看具体审核意见”；执行团队按上一节的组合提示处理。

### 13.6 审核意见弹窗

- 字段、富文本和表格行统一复用一个审核意见弹窗，不为不同模块建立视觉不一致的弹窗。
- 弹窗标题统一为“编辑审核意见”，正文使用多行文本框；主操作为“确定”，已有或新建状态均允许保存。
- “删除”删除当前键并立即清除对应标红状态；无既有意见时可隐藏或禁用删除按钮，具体方式在同一页面保持一致。
- 必须显式设置 `:mask-closable="false"`，避免误点遮罩丢失输入。关闭、取消或 Esc 的行为沿用页面既定规则。
- 保存前执行 `trim()`；空白内容不得形成有效意见。若允许空白保存，应等价于删除该键。
- 原型阶段未接后端时必须明确属于本地演示，不得提示“已提交服务器”。

### 13.7 统一视觉与无障碍状态

- 有审核意见的字段、富文本区域及表格行统一使用淡红背景 `#fff1f0`。
- 已标红行悬停背景统一为 `#ffe7e5`；普通可点击审核行可使用现有轻蓝悬停背景 `#f8fbff`。
- 键盘焦点使用 `2px solid #ff7875`；表格行采用内缩 `outline-offset: -2px`，标题按钮可采用同样内缩规则。
- 可点击审核入口显示 `cursor: pointer`。颜色不能作为唯一提示，必须同时提供模块提示文案、可聚焦入口和审核意见弹层。
- 标红样式只由有效审核意见数据控制，禁止通过项目状态、固定行号或硬编码 CSS 永久标红。
- 长审核意见使用 `white-space: pre-wrap`、`overflow-wrap: anywhere` 和约 `1.6` 行高；弹层建议宽度 `300px`，最大宽度不超过 `60vw`。

建议复用以下语义类，不得按页面重复发明近似类名和色值：

```css
.review-has-comment { background-color: #fff1f0 !important; }
.detail-table tr.review-row-has-comment > td { background: #fff1f0; }
.detail-table tr.review-row-has-comment:hover > td { background: #ffe7e5; }
.review-label-trigger { cursor: pointer; }
.review-label-trigger:focus-visible,
.detail-table tr.review-row-has-comment:focus-visible {
  outline: 2px solid #ff7875;
  outline-offset: -2px;
}
```

### 13.8 Vue 2.6 实现约定

- 使用 Options API、`computed` 和 `methods`；不得使用 Vue 3 `setup` 或 Composition API。
- 将审核意见读取、有效性判断、样式判断和行前缀匹配集中为公共方法，避免在模板内散落不同判断。
- 使用 `ReviewCommentLabel` 展示字段或小标题意见；行级意见可复用统一 Popover 或统一详情弹窗。
- 审核模式下才添加按钮角色和事件；普通查看模式返回空样式对象并直接退出事件方法。
- 推荐的最小读取逻辑如下：

```js
reviewComment (key) {
  const value = (this.reviewComments || {})[key]
  return typeof value === 'string' ? value.trim() : ''
},
rowReviewComment (sectionKey, rowId, fieldKeys = []) {
  const prefix = `${sectionKey}.${rowId}`
  const knownKeys = fieldKeys.map(key => prefix + '.' + key)
  const extraKeys = Object.keys(this.reviewComments || {})
    .filter(key => key.indexOf(prefix + '.') === 0 && !knownKeys.includes(key))
    .sort()
  return [prefix].concat(knownKeys, extraKeys)
    .map(key => this.reviewComment(key))
    .filter(Boolean)
    .join('\n')
},
saveReviewComment (key, value) {
  const text = typeof value === 'string' ? value.trim() : ''
  if (text) this.$set(this.reviewComments, key, text)
  else this.$delete(this.reviewComments, key)
}
```

- 调用行级读取方法时，按表格显示顺序传入 `fieldKeys`；合并展示整行意见及所有有效单元格意见，未知字段键追加展示。该拼接仅用于展示，不回写到原始意见正文。
- 修改页加载数据时使用 `{ ...defaults.reviewComments, ...(payload.reviewComments || {}) }` 合并，确保新增键可直接生效。
- `reviewComments` 的对象引用必须保持响应式；接口返回后整体替换时使用新对象，局部增删时使用 `$set`/`$delete`。
- 页面提交或保存草稿时将 `reviewComments` 与业务表单 JSON 一并提交，不建立只存在于 DOM、组件内部或 CSS 中的意见状态。

### 13.9 人工验收清单

- 审核页的可回写字段、富文本小标题和所有有效数据行均能通过鼠标、Enter 和 Space 打开意见弹窗。
- 操作按钮不会触发行级审核弹窗；普通查看页不会出现审核入口。
- 新增意见后目标区域立即标红，再次打开可看到原文并修改；删除后 JSON 键和标红同时消失。
- 刷新并使用后端返回的同结构 JSON 后，字段、富文本和表格行能自动恢复标红与查看交互。
- 表格排序、插入和删除行后，审核意见仍跟随稳定行 ID，不串行、不丢失。
- 模块无有效意见时不显示修改提示；有任意有效意见时显示与模块交互方式匹配的提示文案。
- 长意见、换行、连续英文或数字在弹层中完整换行，不溢出；遮罩点击不能关闭编辑弹窗。
- 修改申请页只允许查看审核意见，不意外改写意见；保存业务内容时原有 `reviewComments` 不被清空。

## 14. 填写页提示与报告表单

### 输入提示与空状态入口

- 项目申请草稿及进展/结项填写页（含录入弹窗）的蓝色输入提醒统一使用 `14px`、`#5b8ff9`。覆盖输入框、文本域 placeholder、下拉占位、富文本空内容提示及字段旁空值提醒；须显式设置提示字号，避免继承输入正文的 `16px`。
- 提示样式仅作用于占位文本或提示节点；填写正文、字段标签、校验错误、普通说明和工具栏按各自层级显示。原生 placeholder 使用 `opacity: 1`。
- 项目草稿的“点击添加产出”“点击添加附件”、进展/结项的“点击添加附件”空状态文案使用 `#5b8ff9`。仅针对描述文字设置颜色，不将空状态图片、容器及所有蓝色按钮一并改色。
- 新增同类填写页面复用上述提示规则；提示在用户填写内容后按原交互消失。空状态添加入口保留鼠标、Enter 和 Space 操作。

### 进展/结项填写页

- “报告填写日期”在新建报告或加载无日期草稿时默认取浏览器本地今日，使用 `YYYY-MM-DD`，允许修改；已保存日期须原样回显。不得硬编码今日或使用 UTC 日期截取导致跨时区偏差，也不得在用户编辑过程中反复重置。
- 日期标签和输入框占左侧半行，与其他半行字段对齐；外层字段仍跨整行，保留整行 `#edf1f5` 灰色底部分隔线。
- 收益指标成果各类型表格末行使用链接按钮“添加更多成果”，不带加号图标，调用该类型的新增成果操作。“添加更多类型的收益”是独立操作，保留其既有文案与加号。
- 复用 `src/mock/report-drafts.js` 时注意当前存储属于本地演示，不能当作已接入后端的数据流程。

### 人工验收

- 在项目草稿、提交进展、提交结项的相关空字段与弹窗中核对提示字号、颜色；输入后确认正文层级及提示消失行为。
- 在无产出或无附件时核对添加文案颜色与点击、键盘入口；有数据时确认列表正常。
- 分别检查报告新建默认日期、手动改日期、保存后重进回显、半行控件与整行灰线。
- 核对各成果类型的“添加更多成果”无图标且打开正确新增入口。
